- id: resil-01-ocr-fallback
  name: Implement resilient fallback in OCR Service
  type: auto
  files: [src/lib/ocr-service.ts]
  action: |
    Modify `extractTextWithVision` inside `src/lib/ocr-service.ts` to implement try/catch page-by-page fallback:
    1. Import type `PDFDocument` from `pdf-lib` statically using `import type { PDFDocument } from 'pdf-lib';`.
    2. Declare `let PDFDocumentClass: typeof PDFDocument;` and `let pdfDoc: PDFDocument | undefined = undefined;` in the outer function scope before the `try` block. Assign `PDFDocumentClass` during the dynamic import: `const { PDFDocument: loadedClass } = await import('pdf-lib'); PDFDocumentClass = loadedClass;`.
    3. Wrap the dynamic `pdf-lib` loading, page count query, and chunk preparation loop inside the same main try/catch block so that any loading or splitting failures are handled.
    4. If loading or splitting throws an error, trigger whole-document OCR fallback by calling `extractChunkWithVision(pdfBuffer, 0)`.
    5. Add retry loop for chunk-level processing (up to 2 attempts, 2 seconds delay between retries).
    6. If chunk processing fails after retries, fallback to single-page processing only for pages within the failed chunk.
    7. In single-page processing, use `pdfDoc` safely by adding a TS guard `if (!pdfDoc) throw new Error('PDF document not loaded');`.
    8. Generate page-level PDF buffers dynamically using `PDFDocumentClass.create()`, `copyPages`, and `save()`.
    9. Execute single-page tasks with a lower concurrency limit of 2, retrying single-page failures up to 2 times with exponential backoff delays (2s, then 4s).
    10. Report fallback status using `onProgress` callbacks.
    11. Export `runWithConcurrencyLimit` helper from `ocr-service.ts` to allow direct testing.
  verify: npm run lint
  done: OCR service compiles and meets resilience pattern specifications.
